# Scan, review and hand off

For users interpreting evidence. [Home](../README.md) · [Usage](USAGE.md) · [Coverage](../skills/agrimap-golden-lint-skills/references/COVERAGE.md).

Select exact scope/source/parser prerequisites, scan to stdout, inspect source health and per-rule denominators, then review findings. Retain the complete report in host memory or an independently authorized external location. Explain a finding by its original report/finding identities. Export only through a new authorized external destination. Neither operation refreshes evidence.

A compatible canonical baseline report or --base-ref establishes matching pre-existing findings across line/comment shifts. Full current findings always remain. A touched file does not prove that each finding was introduced. Modified-file unmatched findings remain unknown; a new path can be introduced only under the same contract. Changed rules/source/parser, partial baselines, renames and refactors can invalidate attribution. --target-ref analyzes immutable committed blobs; the default analyzes working-tree bytes including untracked content. Local relative TypeScript aliases/re-exports resolve in memory; external framework and tsconfig alias contexts and semantic public export compatibility remain unavailable.

Owner-approved library facade/store islands, public aliases, OAuth response/redirect behavior and HTTP jobs need exact scoped evidence. Current detectors do not accuse those boundaries based on signatures alone. SQL naming/business verbs, seed/index/cascade/data/result/error behavior require owner evidence. Reference/schema/docs SQL are excluded as declared, without claiming their deployment role was determined.

Impact and manageability are independent. Current static evidence sets both unknown. Identify affected consumers/contracts, equivalence obligations, containment and rollback before proposing any exact correction. no-effect-proven requires all relevant behavior/public/wire/data observables unchanged; test/build success alone cannot prove it. Manageable internal effects recommend owner approval for the scope, never automatic edits.

Upstream integration is only a supporting read-only routing proposal. This package does not replace lane skills or create a second lifecycle. Source maintenance updates docs/changelog only when explicitly assigned package work; consumer scans never do so.
