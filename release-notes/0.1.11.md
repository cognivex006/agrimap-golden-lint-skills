# 0.1.11

เพิ่มการตรวจค่าที่ฝังตรงในโค้ด (hardcode) ทุก lane ที่รองรับ พร้อม tier ของ Golden และทะเบียนข้อยกเว้นที่จำข้ามรอบ

- 7 class: `HC-SECRET`, `HC-ENVURL`, `HC-PROXYBYPASS`, `HC-EXTURL`, `HC-CONFIG`, `HC-MAGIC`, `HC-SQL` ใช้คำ tier ของ Golden (`MUST` / `SHOULD` / `FREE`) และ `FREE` ไม่เป็น violation
- `violation` เฉพาะ `HC-SECRET` / `HC-ENVURL` ที่ Golden ระบุตรงและ syntax ไม่กำกวม; class อื่นเป็น review-candidate เพราะ applicability (ของใหม่/แตะเดิม/legacy/test scaffold/config-of-record) พิสูจน์จาก syntax ไม่ได้
- ค่า secret ไม่ถูกเขียนลง report, ledger, prompt หรือ index ทุกรณี เก็บเพียง mask และ digest
- ทะเบียน `.agrimap-agent/reports/golden-lint/hardcode-policy.json` เป็น append-only จำ subject จาก class, ค่าที่ normalize แล้ว และ path ของไฟล์ จึงไม่ถามซ้ำเมื่อบรรทัดขยับ แต่ถามใหม่เมื่อค่าเปลี่ยน ไฟล์ย้าย หมด `reviewAfter` หรือมี decision `reopen`
- เพิ่ม operation `policy-update` ที่เขียนได้เฉพาะทะเบียนที่ผู้เรียกระบุ path ตรงทุกตัวอักษร; JSON, report.md, summary.md, index.md และ prompts แสดง hardcode decisions แยกจาก Golden findings
- Exit 3 รวมกรณี hardcode policy needs-review และ scan ไม่เขียนทะเบียนให้เอง

เอกสารใหม่: `docs/HARDCODE-LINT.md` พร้อมอัปเดต USAGE, REPORTING, WORKFLOWS, TROUBLESHOOTING, COMMAND-COOKBOOK, VERSIONS และ Rule mapping

ผลตรวจ: sync, validate และ tests 116/116 ไม่มี failed/skipped โดยใช้ existing trusted TypeScript parser และ dotnet host

ข้อจำกัด: เป็น lexical observation จาก literal ที่ parse ได้ ไม่ได้พิสูจน์ applicability, ไม่ได้ยืนยันว่า proxy route หรือ gateway key มีอยู่จริง, ไม่ execute ปลายทาง และไม่แทน governance ของ third party
